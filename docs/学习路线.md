## 第一站：全局认知

### 1.1 先搞清楚项目在做什么

这个项目的核心目标是：**用户输入一个选题，系统自动生成一篇配图精美的 Markdown 图文**。

整个过程被拆成 **三大阶段**，每个阶段结束后用户都可以介入修改：

```
阶段1（标题选择）
  用户输入选题 → Agent1 生成 3-5 个标题方案 → 用户选择其中一个
  
阶段2（大纲编辑）
  Agent2 根据标题生成大纲（实时流式输出）→ 用户编辑 / AI 优化大纲

阶段3（正文+配图生成）
  Agent3 生成正文 → Agent4 分析配图需求 → Agent5（并行）生成配图 → 合并图文
```

### 1.2 先运行起来，再看代码

1. 按 `README.md` 的「快速开始」章节，配置 `application-local.yml`
2. `mvn spring-boot:run` 启动后端
3. 打开 `http://localhost:8567/api/doc.html` 看接口文档
4. 在 `ArticleController` 对应的接口页面，**手工调用一次完整流程**

> **目标**：先体感到系统在做什么，再去看代码会清晰很多。

## 第二站：理解数据模型——Agent 之间靠什么通信

在多 Agent 系统中，最关键的问题是：**各个 Agent 之间如何传递数据？**

本项目的答案是 **`ArticleState`**——一个贯穿全程的状态对象。

### 2.1 读这个文件


### 2.2 理解其中的字段演变

`ArticleState` 的字段随着阶段推进被逐步填充：

| 字段 | 由哪个 Agent 填充 | 说明 |
|------|------------------|------|
| `topic` / `style` | 用户输入 | 初始输入 |
| `titleOptions` | Agent1（TitleGeneratorAgent） | 标题方案列表 |
| `title` | 用户选择后 | 选定的标题 |

| `content` | Agent3（ContentGeneratorAgent） | 正文（带占位符） |
| `imageRequirements` | Agent4（ImageAnalyzerAgent） | 每段需要什么图 |
| `images` | Agent5（ParallelImageGenerator） | 实际图片 URL |

## 第三站：理解单个 Agent——一个节点如何工作

### 3.1 Spring AI Alibaba 的 NodeAction 接口

每个 Agent 都实现了 `NodeAction` 接口，核心方法只有一个：

```java
public interface NodeAction {
    Map<String, Object> apply(OverAllState state) throws Exception;
}
```

- **输入**：`OverAllState`（StateGraph 的全局状态，可以用 key 取出任意值）
- **输出**：`Map<String, Object>`（这个 Map 会被合并回全局状态）

### 3.2 最简单的 Agent：先读 TitleGeneratorAgent

```
src/main/java/com/yupi/template/agent/agents/TitleGeneratorAgent.java
```

读代码时关注以下三步：

**Step 1：从状态中取输入**
```java
String topic = state.value(INPUT_TOPIC)
        .map(Object::toString)
        .orElseThrow(() -> new IllegalArgumentException("缺少选题参数"));
```

**Step 2：拼接 Prompt，调用大模型**
```java
String prompt = PromptConstant.AGENT1_TITLE_PROMPT

ChatResponse response = chatModel.call(new Prompt(new UserMessage(prompt)));
String content = response.getResult().getOutput().getText();
```

**Step 3：解析结果，写入状态**
```java
List<ArticleState.TitleOption> titleOptions = GsonUtils.fromJson(content, ...);
return Map.of(OUTPUT_TITLE_OPTIONS, titleOptions);
```

## 第四站：StateGraph 编排——多个节点如何串联

这是整个项目最核心的部分。

### 4.1 读 ArticleAgentOrchestrator

```
src/main/java/com/yupi/template/agent/ArticleAgentOrchestrator.java
```

### 4.2 理解三阶段图的构建

阶段1：最简单的图，只有一个节点

```java
private StateGraph buildPhase1Graph() throws GraphStateException {
    return new StateGraph(keyStrategyFactory)
            .addNode("title_generator", node_async(titleGeneratorAgent))
            .addEdge(START, "title_generator")
            .addEdge("title_generator", END);
}
```

阶段3：四个节点顺序执行的图

```java
private StateGraph buildPhase3Graph() throws GraphStateException {
    return new StateGraph(keyStrategyFactory)
            .addNode("content_generator",       node_async(contentGeneratorAgent))
            .addNode("image_analyzer",          node_async(imageAnalyzerAgent))
            .addNode("parallel_image_generator",node_async(parallelImageGenerator))
            .addNode("content_merger",          node_async(contentMergerAgent))
            .addEdge(START,              "content_generator")
            .addEdge("content_generator","image_analyzer")
            .addEdge("image_analyzer",   "parallel_image_generator")
            .addEdge("parallel_image_generator","content_merger")
            .addEdge("content_merger",   END);
}
```

数据流如下：

```
START
  │ inputs: {taskId, mainTitle, outline, style, enabledImageMethods}
  ▼
content_generator  ──输出 content──▶  image_analyzer
                                           │
                              输出 contentWithPlaceholders
                              输出 imageRequirements
                                           │
                                           ▼
                                parallel_image_generator
                                           │
                              输出 images（List<ImageResult>）
                                           │
                                           ▼
                                  content_merger
                                           │
                              输出 fullContent（最终图文）
                                           │
                                          END
```

### 4.3 理解 KeyStrategyFactory 的作用

图中各节点共享一个 `OverAllState`，当多个节点输出同一个 key 时，需要定义合并策略：

```java
private KeyStrategyFactory createKeyStrategyFactory() {
    return () -> {
        HashMap<String, KeyStrategy> strategies = new HashMap<>();
        strategies.put(KEY_CONTENT, new ReplaceStrategy());   // 后写入的直接覆盖
        strategies.put(KEY_IMAGES,  new ReplaceStrategy());
        // ...
        return strategies;
    };
}
```

本项目所有 key 都使用 `ReplaceStrategy`（替换策略），即后面节点的输出会覆盖前面的值。

> **学习要点**：`StateGraph` = 节点（Node）+ 边（Edge）+ 状态策略（KeyStrategy）。  
> 节点是 Agent，边是执行顺序，状态策略决定数据如何合并。

## 第五站：流式输出——用户为何能看到实时打字效果

### 5.1 问题来源

Agent 内部调用 LLM 流式接口时，产生的 token 需要**穿透 StateGraph 框架**传递到 HTTP 响应中。但 `StateGraph` 的 `OverAllState` 要求所有值可序列化，`Consumer<String>` 这种函数接口无法序列化。

### 5.2 解决方案：ThreadLocal

```
src/main/java/com/yupi/template/agent/context/StreamHandlerContext.java
```

```java
public class StreamHandlerContext {
    // 用 ThreadLocal 保存 streamHandler，不放进 StateGraph
    private static final ThreadLocal<Consumer<String>> STREAM_HANDLER = new ThreadLocal<>();

    public static void set(Consumer<String> handler) { STREAM_HANDLER.set(handler); }
    public static Consumer<String> get()             { return STREAM_HANDLER.get(); }
    public static void clear()                        { STREAM_HANDLER.remove(); } // 务必清理，防止内存泄漏
}
```

### 5.3 使用流程

在 `ArticleAgentOrchestrator` 中，执行图之前设置，执行完成后清理：

```java
// 在 executePhase2_GenerateOutline 中
StreamHandlerContext.set(streamHandler);   // ① 执行前注入
try {
    compiledGraph.invoke(inputs);          // ② 图执行期间，Agent 可从 ThreadLocal 取到
} finally {
    StreamHandlerContext.clear();          // ③ 执行后清理（finally 保证一定执行）
}
```

Agent 内部只需要调用：

```java
Consumer<String> streamHandler = StreamHandlerContext.get();
streamHandler.accept("AGENT2_STREAMING:" + chunk);
```

> **学习要点**：ThreadLocal 解决了「函数对象无法序列化但又需要跨层传递」的经典问题。  
> 注意 `finally` 块中清理 ThreadLocal 是工程实践中的必要操作。

## 第六站：并行执行——多张图片为何同时生成

### 6.1 读 ParallelImageGenerator

```
src/main/java/com/yupi/template/agent/parallel/ParallelImageGenerator.java
```

### 6.2 并行策略设计

按配图类型（imageSource）分组，同类型串行、不同类型并行：

```
imageRequirements = [
  {position:1, imageSource: PEXELS,   keywords: "mountain"},
  {position:2, imageSource: MERMAID,  prompt: "flowchart LR..."},
  {position:3, imageSource: PEXELS,   keywords: "ocean"},
  {position:4, imageSource: SVG_DIAGRAM, prompt: "..."},
]

分组后：
  PEXELS 组      → [position:1, position:3]  → 串行处理
  MERMAID 组     → [position:2]              → 独立线程
  SVG_DIAGRAM 组 → [position:4]              → 独立线程

三组同时并行，互不等待
```

### 6.3 核心并发代码

```java
List<CompletableFuture<Void>> futures = groupedBySource.entrySet().stream()
        .map(entry -> CompletableFuture.runAsync(() -> {
            // 每种 imageSource 在独立线程中串行处理
            for (ArticleState.ImageRequirement req : entry.getValue()) {
                ImageGenerationTool.ImageGenerationResult result =
                        imageGenerationTool.generateImageDirect(...);
                if (result.isSuccess()) {
                    allImages.add(imageResult);  // CopyOnWriteArrayList 保证线程安全
                    streamHandler.accept(IMAGE_COMPLETE + GsonUtils.toJson(imageResult));
                }
            }
        }))
        .toList();

CompletableFuture.allOf(futures.toArray(new CompletableFuture[0])).join(); // 等所有任务完成
```

> **学习要点**：  
> - `CompletableFuture.runAsync()` 提交异步任务  
> - `CompletableFuture.allOf(...).join()` 等待全部完成  
> - `CopyOnWriteArrayList` 在并发写场景保证线程安全  
> - 每生成一张图立即通过 SSE 推送，让用户看到实时进度

## 第七站：AOP 日志追踪——执行记录自动采集

### 7.1 问题：如何无侵入地记录每个 Agent 的执行情况？

答案是 Spring AOP + 自定义注解。

### 7.2 读这两个文件

```
src/main/java/com/yupi/template/annotation/AgentExecution.java
src/main/java/com/yupi/template/aop/AgentExecutionAspect.java
```

### 7.3 使用方式

在 Service 层方法上加注解：

```java
@AgentExecution(value = "agent1_generate_titles", description = "生成标题方案")
public void generateTitles(ArticleState state, Consumer<String> streamHandler) {
    // 业务代码无需关心日志记录
}
```

AOP 切面自动完成：

```java
@Around("@annotation(agentExecution)")
public Object aroundAgentExecution(ProceedingJoinPoint pjp, AgentExecution agentExecution) {
    long startTime = System.currentTimeMillis();
    // 构建日志对象
    AgentLog agentLog = AgentLog.builder()
            .agentName(agentExecution.value())
            .status("RUNNING")
            .build();
    try {
        Object result = pjp.proceed();   // 执行原方法
        agentLog.setStatus("SUCCESS");
        agentLog.setDurationMs(...);
        return result;
    } catch (Throwable e) {
        agentLog.setStatus("FAILED");
        agentLog.setErrorMessage(e.getMessage());
        throw e;
    } finally {
        agentLogService.saveLogAsync(agentLog); // 异步保存，不阻塞主流程
    }
}
```

> **学习要点**：`@Around` 环绕通知是最强大的 AOP 类型，可以在方法执行前后插入任意逻辑，不影响业务代码。  
> `agentLogService.saveLogAsync()` 使用异步保存，避免日志记录影响主流程性能。

## 第八站：配图策略模式——新增配图方式只要加一个类

### 8.1 为什么用策略模式？

当前支持 6 种配图方式（Pexels、Mermaid、Iconify、Emoji、NanoBanana、SVG），未来可能增加更多。如果用 `if-else` 硬编码，每次新增都要修改核心逻辑，违反开闭原则。

### 8.2 阅读枚举和接口

```
src/main/java/com/yupi/template/model/enums/ImageMethodEnum.java
src/main/java/com/yupi/template/service/ImageServiceStrategy.java
```

### 8.3 策略注册机制

每个配图服务的 `@Service` 注解 Bean 名与枚举值一致：

```java
@Service("PEXELS")
public class PexelsService implements ImageSearchService { ... }

@Service("MERMAID")
public class MermaidService implements ImageSearchService { ... }

@Service("NANO_BANANA")
public class NanoBananaService implements ImageSearchService { ... }
```

策略选择器通过 Spring 容器动态查找：

```java
// ImageServiceStrategy 中
@Autowired
private Map<String, ImageSearchService> serviceMap;  // Spring 自动注入所有实现

public ImageSearchService getService(String method) {
    return serviceMap.get(method);  // 按名称获取对应实现
}
```

### 8.4 如何新增一种配图方式（参考 README 扩展指南）

1. 在 `ImageMethodEnum` 添加枚举值
2. 创建实现 `ImageSearchService` 接口的类，`@Service` 名与枚举值一致
3. 完成！策略选择器自动发现新服务

> **学习要点**：Spring 的 `@Autowired Map<String, Interface>` 会自动将所有实现类按 Bean 名注入，这是策略模式与 Spring 结合的经典写法。

## 第九站：SSE 实时推送——进度条背后的通信机制

### 9.1 SSE 是什么

Server-Sent Events（服务端推送事件）：服务端 → 客户端的单向实时数据流，基于 HTTP 长连接，适合「生成中」的流式场景。

### 9.2 读 SseEmitterManager

```
src/main/java/com/yupi/template/manager/SseEmitterManager.java
```

核心逻辑：用 `ConcurrentHashMap` 管理所有连接，按 `taskId` 索引：

```java
private final Map<String, SseEmitter> emitterMap = new ConcurrentHashMap<>();

public SseEmitter createEmitter(String taskId) {
    SseEmitter emitter = new SseEmitter(SSE_TIMEOUT_MS);
    emitter.onTimeout(() -> emitterMap.remove(taskId));    // 超时自动清理
    emitter.onCompletion(() -> emitterMap.remove(taskId)); // 完成自动清理
    emitterMap.put(taskId, emitter);
    return emitter;
}

public void send(String taskId, String message) {
    SseEmitter emitter = emitterMap.get(taskId);
    emitter.send(SseEmitter.event().data(message));
}
```

### 9.3 完整的 SSE 消息类型（对照 README）

```
AGENT1_COMPLETE      → 标题方案列表已就绪，前端展示选择界面
AGENT2_STREAMING     → 大纲内容正在流式输出
AGENT2_COMPLETE      → 大纲生成完成
AGENT3_STREAMING     → 正文内容正在流式输出
AGENT3_COMPLETE      → 正文生成完成
AGENT4_COMPLETE      → 配图需求分析完成
IMAGE_COMPLETE:{}    → 单张图片生成完成（携带图片数据）
AGENT5_COMPLETE      → 所有配图生成完成
MERGE_COMPLETE       → 图文合并完成，文章已就绪
ERROR                → 发生错误
```

> **学习要点**：每条 SSE 消息既是状态通知，也是前端渲染的触发器。前端根据消息类型决定刷新哪个 UI 模块。

## 第十站：整体业务串联——从 HTTP 请求到完整图文的全链路

### 10.1 读控制器

```
src/main/java/com/yupi/template/controller/ArticleController.java
```

关注三个核心接口：
- `POST /article/start` — 创建任务，触发阶段1
- `POST /article/outline` — 用户确认标题，触发阶段2
- `POST /article/generate` — 用户确认大纲，触发阶段3
- `GET /article/sse/{taskId}` — 建立 SSE 连接，接收实时进度

### 10.2 读服务层

```
src/main/java/com/yupi/template/service/ArticleAgentService.java（或 impl 目录下的实现）
```

服务层的职责是：将 HTTP 层的 DTO 转换为 `ArticleState`，调用 `ArticleAgentOrchestrator`，并通过 `SseEmitterManager` 推送进度。

### 10.3 全链路流程图

```
前端用户
  │ ① 输入选题，POST /article/start
  ▼
ArticleController
  │ 创建 ArticleState，存入 Redis
  ▼
ArticleAgentOrchestrator.executePhase1_GenerateTitles()
  │ buildPhase1Graph() → compiledGraph.invoke()
  ▼
TitleGeneratorAgent.apply()
  │ LLM 调用，返回 titleOptions
  ▼
SseEmitterManager.send("AGENT1_COMPLETE")
  │
  │ ② 用户选择标题，POST /article/outline
  ▼
ArticleAgentOrchestrator.executePhase2_GenerateOutline()
  │ buildPhase2Graph() → compiledGraph.invoke()
  ▼
OutlineGeneratorAgent.apply()
  │ 流式 LLM 调用，每个 token → StreamHandlerContext → SseEmitterManager.send("AGENT2_STREAMING:token")
  ▼
SseEmitterManager.send("AGENT2_COMPLETE")
  │
  │ ③ 用户确认大纲，POST /article/generate
  ▼
ArticleAgentOrchestrator.executePhase3_GenerateContent()
  │ buildPhase3Graph() → compiledGraph.invoke()
  ▼
content_generator → image_analyzer → parallel_image_generator → content_merger
  │                      │                   │                        │
  │                      │          并行生成多张图片              合并图文
  │                      │          每张完成发送IMAGE_COMPLETE
  └──────────────────────┴───────────────────┴────────────────────────┘
  最终: SseEmitterManager.send("MERGE_COMPLETE")
        SseEmitterManager.complete(taskId)   // 关闭 SSE 连接
```
