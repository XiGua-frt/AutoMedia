## 1. 产品概述

**AI 爆款文章创作器**是一款基于多智能体编排的 AI 内容创作平台。用户只需输入一个主题，系统便通过串联多个专职 AI 智能体，自动完成标题生成、大纲规划、正文写作、配图搜索/生成、图文合成等完整创作流程，最终输出一篇图文并茂的 Markdown 格式文章。

### 核心价值

| 维度 | 描述 |
|------|------|
| **自动化** | 全流程无需手动干预，6 个智能体协同创作 |
| **个性化** | 支持科技、情感、教育、幽默 4 种文章风格 |
| **知识增强** | RAG 知识库检索，用私有素材库增强创作质量 |
| **多样化配图** | 集成 6 种配图来源，AI 生图 + 图库搜索 + 降级兜底 |
| **实时反馈** | 基于 SSE 的流式输出，让用户实时看到创作进度 |
| **可介入性** | 标题选择、大纲编辑两个节点允许用户人工干预 |

### 4.2 文章管理模块

#### 文章生命周期

```
PENDING → PROCESSING → COMPLETED
                     → FAILED
```

#### 文章创作阶段（Phase）

```
PENDING
  └─ TITLE_GENERATING   (Agent 1 运行中)
       └─ TITLE_SELECTING   (等待用户选择标题)
            └─ OUTLINE_GENERATING  (Agent 2 运行中)
                 └─ OUTLINE_EDITING   (等待用户编辑大纲)
                      └─ CONTENT_GENERATING  (Agent 3/4/5 运行中)
```

Phase 状态机在 `ArticlePhaseEnum.can_transition_to()` 中强制校验，防止非法跳转。

#### 主要 API

| 路由 | 方法 | 功能 |
|------|------|------|
| `/api/article/` | POST | 创建文章并触发阶段1 |
| `/api/article/` | GET | 分页查询文章列表 |
| `/api/article/{id}` | GET | 获取文章详情 |
| `/api/article/{id}` | DELETE | 删除文章（软删除） |
| `/api/article/{id}/select-title` | POST | 用户选择标题，触发阶段2 |
| `/api/article/{id}/confirm-outline` | POST | 用户确认大纲，触发阶段3 |
| `/api/article/{id}/sse` | GET | 订阅文章 SSE 事件流 |
| `/api/article/{id}/export` | GET | 导出 Markdown |

#### 文章导入 / 导出

- 导出：将 `content` 字段作为 `.md` 文件下载
- 导入：POST 上传 `.md` 文件，解析标题与正文保存入库

### 4.3 核心创作模块（多智能体）

整个创作流程由 `ArticleAgentOrchestrator` 统一调度，分为 3 个用户可感知阶段：

#### 阶段 1：标题生成（Agent 1）

- **触发**：用户提交主题 + 风格，后台异步执行
- **模型**：通义千问（`qwen-plus`）
- **输出**：3~5 个标题备选方案（含推荐理由）
- **交互**：生成完毕后通过 SSE 推送 `TITLES_GENERATED` 事件，前端展示选择界面

```
Prompt 模板：
  AGENT1_TITLE_PROMPT.replace("{topic}", topic) + 风格 Prompt
```

#### 阶段 2：大纲生成（Agent 2）

- **触发**：用户选定标题后
- **模型**：通义千问
- **输出**：结构化大纲（章节列表，每节含标题 + 描述）
- **交互**：支持 **流式输出**（SSE `AGENT2_STREAMING`），用户可在大纲生成后编辑

#### 阶段 3：正文 + 配图 + 合成（Agent 3/4/5）

| 子阶段 | 智能体 | 说明 |
|--------|--------|------|
| 正文生成 | ContentGeneratorAgent | 按大纲逐节生成 Markdown 正文，流式输出 |
| 配图分析 | ImageAnalyzerAgent | 分析正文，输出每节的图片关键词 + 推荐配图方式 |
| 配图生成 | ParallelImageGenerator | **并行**调用图片服务，可配最大并发数（默认 3） |
| 图文合成 | ContentMergerAgent | 将图片 URL 按位置插入 Markdown 正文 |

**并行配图控制**参数（`config.py`）：

```python
agent_image_max_concurrency: int = 3   # 最大并行数
agent_image_fail_fast: bool = True     # 任意失败立即终止
```

### 4.4 智能配图模块

系统采用 **策略模式**（`ImageServiceStrategy`）统一管理 6 种配图来源，并提供自动降级机制。

#### 配图来源

| 类型 | 枚举值 | 说明 | AI 生图 |
|------|--------|------|---------|
| Pexels 图库 | `PEXELS` | 按关键词搜索高质量照片 | ✗ |
| Nano Banana | `NANO_BANANA` | 调用 Gemini 模型生图（16:9） | ✓ |
| Mermaid 流程图 | `MERMAID` | 通过 `mmdc` CLI 生成 SVG 流程图 | ✓ |
| Iconify 图标 | `ICONIFY` | 搜索矢量图标，适合技术文章 | ✗ |
| Bing 表情包 | `EMOJI_PACK` | 爬取 Bing 图片搜索结果 | ✗ |
| SVG 示意图 | `SVG_DIAGRAM` | AI 生成 SVG 代码并渲染 | ✓ |
| Picsum（降级） | `PICSUM` | 随机占位图，兜底使用 | ✗ |

#### 图片获取流程

```
ImageAnalyzerAgent 分析图片需求
        ↓
ImageServiceStrategy.get_image_and_upload(image_source, request)
        ↓
  ① 解析 image_source → ImageMethodEnum
  ② 调用对应 Service.get_image_data()
  ③ 上传到腾讯云 COS（按 method 分目录）
  ④ 返回 COS URL
        ↓ 失败时
  降级 → Picsum 兜底图 → 同样上传 COS
```

#### COS 存储目录映射

```
pexels/         # Pexels 图片
nano-banana/    # AI 生图
mermaid/        # 流程图
iconify/        # 图标
emoji-pack/     # 表情包
svg-diagram/    # SVG 示意图
fallback/       # 降级图片
```

### 4.5 VIP 会员与支付模块

#### 产品设计

| 产品 | 枚举 | 价格 | 描述 |
|------|------|------|------|
| 永久会员 | `VIP_PERMANENT` | $199.00 | 无限创作配额，终身有效 |

#### Stripe 支付流程

```
1. 用户点击升级 VIP
        ↓
2. POST /api/payment/create-session
   → 创建 Stripe Checkout Session
   → 写入 payment_record (status=PENDING)
   → 返回 session.url
        ↓
3. 前端跳转 Stripe 托管支付页面
        ↓
4. 支付成功 → Stripe 回调 Webhook
   POST /api/payment/webhook
   → 验证签名 (stripe.Webhook.construct_event)
   → handle_payment_success() 幂等处理
   → 更新 payment_record (status=SUCCEEDED)
   → 更新 user (userRole=vip, vipTime=now)
        ↓
5. 用户被跳转到 success_url
```

#### 退款流程

```
POST /api/payment/refund
→ 校验用户为 VIP
→ 查询最近一笔成功支付记录
→ stripe.Refund.create(payment_intent=...)
→ 事务中更新 payment_record (status=REFUNDED)
→ 重置 user.userRole=user, vipTime=NULL, quota=默认值
```

### 4.7 知识管理模块（RAG）

知识管理模块基于 **RAG（Retrieval-Augmented Generation，检索增强生成）** 技术，允许用户上传私有文档（爆款文章素材、写作风格参考、行业知识库等），系统自动将其向量化并存入 Redis Stack，在文章创作时由 `SearchRetrieverAgent` 实时检索相关内容注入 Prompt，显著提升输出质量与领域专业度。

#### 知识管理完整流程

```
用户上传文档（PDF / TXT / MD）
        ↓
文档清洗（去除噪音 · 格式标准化）
        ↓
文本分块（Chunk Splitting，默认 512 Token / 块，重叠 50 Token）
        ↓
向量化（调用 DashScope Embedding API 生成向量）
        ↓
存入 Redis Stack Vector Store（HNSW 索引）
        ↓
文章创作时 SearchRetrieverAgent 语义检索
        ↓
检索结果注入 Context → OutlineGeneratorAgent / ContentGeneratorAgent
```

#### 知识文档管理功能

| 功能 | 说明 |
|------|------|
| 文档上传 | 支持 PDF / TXT / Markdown 格式，单文件大小限制 10MB |
| 文档清洗 | 去除 HTML 标签、控制字符、多余空白；PDF 文字提取 |
| 向量化入库 | 调用 DashScope Embedding API，生成 1536 维向量存入 Redis Stack |
| 语义检索 | 余弦相似度检索，Top-K 返回最相关文本段（默认 K=5） |
| 文档管理 | 查看/删除已上传文档；查看向量化状态（处理中 / 完成 / 失败） |

#### SearchRetrieverAgent 检索逻辑

```python
class SearchRetrieverAgent:
    """RAG 知识检索智能体（Agent 0）"""

    async def run(self, service, state: ArticleState):
        # 1. 构建检索查询词（基于 topic + style）
        query = f"{state.topic} {state.style or ''}"

        # 2. 从 Redis Stack 向量库语义检索
        docs = await vector_store.similarity_search(query, k=5)

        # 3. 将检索结果整合为 context 注入 state
        state.knowledge_context = self._format_context(docs)

        # 4. 记录检索日志（命中文档数、相似度分数）
        logger.info(
            "RAG 检索完成, taskId=%s, hitCount=%d",
            state.task_id, len(docs)
        )
```

#### Context 注入方式

`SearchRetrieverAgent` 输出的 `knowledge_context` 会被后续智能体引用：

| 智能体 | Context 使用方式 |
|--------|----------------|

## 5. 智能体编排设计

### 5.1 六大智能体职责

| 智能体 | 阶段 | 核心职责 | 输入 | 输出 |
|--------|------|----------|------|------|
| `SearchRetrieverAgent` | Phase 0（隐式） | RAG 知识检索，为后续 Agent 提供 Context | topic + style | knowledge_context |
| `TitleGeneratorAgent` | Phase 1 | 生成 3~5 个标题备选方案 | topic + style + context | titleOptions |
| `OutlineGeneratorAgent` | Phase 2 | 流式生成文章大纲 | title + context | outline |
| `ContentGeneratorAgent` | Phase 3 | 流式生成各节正文（含占位符） | outline + context | content |
| `ImageAnalyzerAgent` | Phase 3 | 分析每节配图需求（关键词 + 推荐方式） | content | imageRequirements |
| `ParallelImageGenerator` | Phase 3 | 并行生成 / 搜索所有配图并上传 COS | imageRequirements | images |
| `ContentMergerAgent` | Phase 3 | 将图片 URL 插入正文，生成最终 Markdown | content + images | fullContent |

### 5.2 编排器核心逻辑

```python
# ArticleAgentOrchestrator（含 RAG 检索阶段）

async def execute_phase1(service, state, stream_handler):
    # Agent 0: RAG 知识检索（在标题生成前注入 Context）
    await search_retriever_agent.run(service, state)
    emit(AGENT0_COMPLETE)

    # Agent 1: 标题生成
    await title_agent.run(service, state)
    emit(AGENT1_COMPLETE)

async def execute_phase2(service, state, stream_handler):
    # Agent 2: 大纲生成（携带 knowledge_context）
    await outline_agent.run(service, state, emit)
    emit(AGENT2_COMPLETE)

async def execute_phase3(service, state, stream_handler):
    # Agent 3: 正文生成（携带 knowledge_context）
    await content_agent.run(service, state, emit)
    emit(AGENT3_COMPLETE)

    # Agent 4: 配图需求分析
    await image_analyzer_agent.run(service, state)
    emit(AGENT4_COMPLETE)

    # Agent 5: 并行配图生成
    await service.agent5_generate_images(state, emit)
    emit(AGENT5_COMPLETE)

    # 图文合成
    content_merger_agent.run(service, state)
    emit(MERGE_COMPLETE)
```

### 5.3 异步任务调度

`ArticleAsyncService` 负责将编排器调用包装为独立异步任务：

- 阶段 1/2/3 分别通过 `asyncio.create_task()` 在后台执行
- 每个阶段开始前更新文章 `status=PROCESSING` 和对应 `phase`
- 阶段完成后更新 DB 并发送 SSE 完成事件
- 异常时更新 `status=FAILED` 并推送 `ERROR` 事件

### 5.3 SSE 管理器

`SseEmitterManager`（单例）管理所有活跃的 SSE 连接：

```python
# 注册连接
sse_emitter_manager.register(task_id, queue)

# 发送消息
sse_emitter_manager.emit(task_id, message)

# 完成并关闭
sse_emitter_manager.complete(task_id)
```

## 6. RAG 检索增强生成详解

### 6.1 整体数据流

```
┌─────────────────────────────────────────────────────────┐
│                   离线阶段：知识入库                       │
│                                                         │
│  用户上传文档                                             │
│      ↓                                                  │
│  文档清洗（去噪 · 格式化）                                │
│      ↓                                                  │
│  文本分块（Chunk）                                        │
│      每块 512 Token，相邻块重叠 50 Token                  │
│      ↓                                                  │
│  DashScope Embedding API                                │
│      → 每块生成 1536 维稠密向量                           │
│      ↓                                                  │
│  Redis Stack（HNSW 向量索引）                            │
│      存储：原文 + 向量 + 元数据（文档ID · 分块序号）       │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│                   在线阶段：创作检索                       │
│                                                         │
│  用户提交 topic + style                                  │
│      ↓                                                  │
│  SearchRetrieverAgent                                   │
│      构建查询："{topic} {style}"                         │
│      → 生成查询向量（Embedding）                          │
│      → Redis Stack HNSW 近邻检索 Top-K=5                │
│      → 按相似度排序，过滤低分块（阈值 0.75）              │
│      ↓                                                  │
│  组装 knowledge_context（最多 2000 Token）               │
│      ↓                                                  │
│  注入 ArticleState.knowledge_context                    │
│      ↓ context                    ↓ title               │
│  OutlineGeneratorAgent      ContentGeneratorAgent       │
└─────────────────────────────────────────────────────────┘
```

### 6.2 文档分块策略

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `chunk_size` | 512 Token | 每个文本块的最大 Token 数 |
| `chunk_overlap` | 50 Token | 相邻块重叠量，保留上下文连贯性 |
| `separator` | `\n\n` | 优先按段落分割 |
| 最小块长度 | 50 Token | 过短的块（如页眉页脚）自动丢弃 |

### 6.3 向量检索参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `top_k` | 5 | 返回最相似的前 K 个文本块 |
| `score_threshold` | 0.75 | 余弦相似度低于此阈值的结果被过滤 |
| `max_context_tokens` | 2000 | 注入 Prompt 的 context 最大 Token 数 |
| `index_algorithm` | HNSW | Redis Stack 向量索引算法 |
| `distance_metric` | COSINE | 距离度量方式 |

### 6.4 Prompt 注入模板

**OutlineGeneratorAgent Prompt（含 context）：**

```
你是一位专业的内容策划师，请根据以下信息生成文章大纲。

【文章标题】{title}
【写作风格】{style}

【参考素材（来自知识库）】
{knowledge_context}

请基于以上参考素材，生成结构清晰、逻辑严谨的文章大纲...
```

**ContentGeneratorAgent Prompt（含 context）：**

```
你是一位专业的内容创作者，请根据以下信息创作文章正文。

【章节标题】{section_title}
【大纲描述】{section_desc}

【参考知识（来自知识库）】
{knowledge_context}

请结合参考知识，创作内容丰富、专业准确的正文...
```

### 6.5 知识库检索 SSE 事件

RAG 检索阶段新增 SSE 事件类型：

| 事件类型 | 触发时机 | 数据 |
|----------|----------|------|
| `AGENT0_COMPLETE` | SearchRetrieverAgent 完成 | `{ hitCount, avgScore }` |
| `AGENT0_SKIP` | 知识库为空 / 检索无结果时跳过 | `{ reason }` |

## 9. SSE 实时推送协议

客户端通过 `GET /api/article/{id}/sse` 建立 SSE 长连接，服务端按创作进度推送以下事件类型：

| 事件类型 | 触发时机 | 携带数据 |
|----------|----------|----------|
| `AGENT0_COMPLETE` | **SearchRetrieverAgent 检索完成** | `{ hitCount, avgScore }` |
| `AGENT0_SKIP` | **知识库为空 / 无相关结果，跳过检索** | `{ reason }` |
| `AGENT1_COMPLETE` | TitleGeneratorAgent 调用完成 | 无 |
| `TITLES_GENERATED` | 标题方案写入 DB 完成 | `{ titleOptions: [...] }` |
| `AGENT2_STREAMING` | 大纲流式输出中 | `"token..."` （增量文本） |
| `AGENT2_COMPLETE` | 大纲生成完成 | 无 |
| `OUTLINE_GENERATED` | 大纲写入 DB 完成 | `{ outline: {...} }` |
| `AGENT3_STREAMING` | 正文流式输出中 | `"token..."` （增量文本） |
| `AGENT3_COMPLETE` | 正文生成完成 | 无 |
| `AGENT4_COMPLETE` | 配图需求分析完成 | 无 |
| `IMAGE_COMPLETE` | 单张图片生成完成 | `{ position, url, method }` |
| `AGENT5_COMPLETE` | 全部配图完成 | 无 |
| `MERGE_COMPLETE` | 图文合成完成 | 无 |
| `ALL_COMPLETE` | 整个创作流程完成 | `{ articleId }` |
| `ERROR` | 任意阶段发生异常 | `{ message: "..." }` |

### 前端接入示例

```typescript
// utils/sse.ts
const eventSource = new EventSource(`/api/article/${id}/sse`, {
  withCredentials: true
})

eventSource.onmessage = (event) => {
  const { type, data } = JSON.parse(event.data)
  switch (type) {
    case 'TITLES_GENERATED':
      showTitleSelector(data.titleOptions)
      break
    case 'AGENT2_STREAMING':
      appendOutlineToken(data)
      break
    case 'ALL_COMPLETE':
      router.push(`/article/${id}`)
      break
    case 'ERROR':
      showError(data.message)
      break
  }
}
```
